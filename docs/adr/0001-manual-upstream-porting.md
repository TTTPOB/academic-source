# ADR 0001：按需移植上游站点知识

- 状态：Accepted
- 实施情况：持续执行。

## 背景

`src/scansci_pdf/` 是 `Rimagination/scansci-pdf` 在提交 `921f540`（2026-09-23）处的 fork。fork 之后，本项目改了其中 38 个文件、删了约 1.4 万行，并把选源和任务编排移到了 `academic_source`。上游在同一时期又有 115 次提交。两边的结构已经对不上，但上游仍在积累有用的东西：各出版商站点的解析规则和反爬应对。

## 决策

不与上游做 Git 合并。某个站点需要修复或更新时，去上游找对应的改动，手工移植需要的那部分，并保留版权与归属信息。

移植如果要改变某个 provider 的行为，按 [ADR 0002](0002-provider-ownership.md) 处理。

## 理由与替代方案

合并上游会把站点修复连同上游的编排、依赖和接口改动一起带进来，而后者正是本项目已经替换掉的部分，每次合并都要重新解决同一批冲突。手工移植把每次改动限定在一个站点上。

## 后果

上游的修复不会自动到达本项目，站点失效时需要有人主动去上游查。

## 验证要点

每次移植在提交信息里写明对应的上游提交或文件，并为受影响的站点补回归测试。移植不应改变其他来源的顺序或行为。
