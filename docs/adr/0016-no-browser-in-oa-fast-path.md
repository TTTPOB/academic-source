# ADR 0016：OA 快路径只用 HTTP，删除浏览器重试

- 状态：Accepted
- 实施情况：已实现。单元测试确认快路径不开浏览器；线上验证见「验证要点」。

## 背景

OA 快路径用普通 HTTP 下载 Unpaywall、OpenAlex、PMC 给出的地址。原先在 CDP 模式下，HTTP 被拦截的地址里前两个还会交给浏览器重试（来源名 `OACDP`）：在生产 Chrome 里打开文章页，在标签页内重新下载那个 PDF；还不行，就取页面上找到的第一个 PDF 链接再试。

这一步有两个问题：

1. 它排在出版商来源前面。快路径整体失败后才轮到来源链，而 Elsevier 这类出版商的官方 API 就在来源链里。结果是先开浏览器，再用 API。
2. 页面上找到的第一个 PDF 链接未必是这篇论文。10.1016/j.cell.2018.11.029 的文章页没有声明 PDF 地址，浏览器取到了页脚里的 cell.com 招聘广告 PDF；文件能打开，被当作论文收下，没有任何警告。同一篇论文用 Elsevier API 约 2 s 就能拿到正式版。

服务日志里这一步重试过 9 篇论文，全部失败，每次 0.5–5 s；唯一一次成功就是上面这份错文件。

## 决策

删除 `OACDP`。OA 快路径只用 HTTP，被拦截的地址不再用浏览器重试，直接进入来源链，由出版商自己的来源处理（官方 API、出版商浏览器路径等）。

所有来源都失败后是否再加一层浏览器兜底，以后有需要时再考虑。

正文结果的缓存版本加 1，清掉那份已缓存的错文件。

## 理由与替代方案

- **把浏览器重试挪到出版商 HTTP 来源之后**：能让 Elsevier API 先跑，但不解决抓错文件的问题，也没有证据说明它能救回论文。
- **保留重试，但要求下载的 PDF 前两页出现 DOI**：能挡住错文件，但这一步本身没有成功过，加检查只是在维护一段不起作用的代码。

## 后果

- 出版商页面拦截普通 HTTP 时，快路径直接失败，交给来源链；有 API 的出版商因此更快、更准。
- 没有专门来源、又拦截普通 HTTP 的出版商，开放获取论文可能拿不到；这类情况以前也没有靠这一步拿到过。
- 快路径的 HTTP 部分在拿到 HTML 页面时，仍会顺着页面上的 PDF 链接再试最多 3 个，这里同样可能取到不相干的 PDF。

## 验证要点

已验证：

- 单元测试：CDP 模式下，HTTP 候选全被拦截时快路径不开浏览器。

部署后验证：

- 10.1016/j.cell.2018.11.029 由 ElsevierAPI 拿到 Cell 正式版。
- 10.1016/j.neuron.2019.01.056 和 10.1038/s41593-019-0364-9 结果不变（Neuron 正式版、Nature 作者接收稿）。
