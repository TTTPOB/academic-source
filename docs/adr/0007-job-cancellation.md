# ADR 0007：以论文为边界取消获取任务

- 状态：Accepted
- 实施情况：已实现。回归测试覆盖排队及执行中取消、保留产物、服务重启和 HTTP / MCP 接口。

## 背景

批量获取任务进入队列后，调用方需要能够停止尚未执行的工作，同时保留已经取得的论文及产物。浏览器会话由单工作线程管理，来源尝试可能包含不可安全中断的操作。

## 决策

- 新增终态 `cancelled`。尚未启动的任务取消后立即写入这一状态，并从排队统计移除。
- 已启动的任务完成正在处理的论文，不再开始下一篇。取消请求在内存中记录，任务结束后写入 `cancelled`。保留全部已完成论文的结果与产物；未执行的论文不产生结果。
- 取消终态任务时原样返回；未知 ID 在应用层抛 `KeyError`，HTTP 返回 404。HTTP `POST /api/v1/jobs/{job_id}/cancel` 与 MCP `cancel_job(job_id)` 返回各自任务查询使用的投影。

## 理由与替代方案

在论文边界停止可以沿用正常的来源清理、结果保存和产物登记流程。强制中断线程或关闭浏览器会话可能破坏这些步骤，因此不采用；等到整批完成则无法省去后续论文的获取工作。

## 后果

取消接口不等待当前论文完成，调用方可继续轮询，直到状态变为 `cancelled`。任务仍处于运行状态时，重启继续按原规则将其标为 `interrupted`；已持久化的 `cancelled` 不变。

## 验证要点

用阻塞的离线来源验证：排队中取消会唤醒等待方并更新后续任务的排队位置；执行中取消会保留当前及此前论文的结果与产物，并跳过其余论文。校验取消响应与查询投影一致，以及重启后仍能读取 `cancelled` 记录。
