# ADR 0006：已知非开放获取时跳过纯 OA 来源

- 状态：Accepted（用户于 2026-11-19 确认保留）
- 实施情况：已实现（跳过规则在提交 `a6009c3`，元数据超时在 `e888ee1`），单元测试覆盖。生产验收结果见完成报告。

## 背景

`oa_first` 对付费期刊很慢。OA 快路径依次查询 Unpaywall、OpenAlex、Europe PMC 和 PMC；即使前两家已经明确回答“不是开放获取”，后续阶段仍会把 OpenAIRE、DOAJ、CrossrefPage、CORE 逐个试完，才轮到出版商来源。这些元数据查询还和 PDF 下载共用 30 秒的读超时，一次超时就拖住整条链。

## 决策

1. **判定“非开放获取”需要同时满足两个条件**：Unpaywall 和 OpenAlex 都明确返回 `is_oa=false`；四个元数据服务合计没有给出任何候选地址。
2. **判定成立时**，后续阶段跳过 OpenAIRE、DOAJ、CrossrefPage、CORE，直接进入出版商、灰色和机构来源，这些来源之间的顺序不变。服务日志记一行 `skip identifier=... reason=closed_access`。对外的失败原因没有新增。
3. **以下情况不跳过**：只有一家否定；Unpaywall 或 OpenAlex 查询失败；Unpaywall 因未配置邮箱而没有查询；任一服务给出了候选地址，即使下载失败。
4. **OA 元数据查询使用单独的读超时** `source_config.oa_metadata_read_timeout`，默认 8 秒。PDF 下载和其他来源仍用 `read_timeout`。这个键不参与结果缓存键的计算，修改它不会让已有缓存失效。

## 理由与替代方案

- 只凭一家的否定就跳过会更快，但 Unpaywall 和 OpenAlex 对机构仓储的覆盖不同，一家没收录的绿色 OA 版本另一家可能有。用户于 2026-11-19 确认保持两家都否定才跳过。
- CrossrefPage 抓取的是出版商页面上声明的 PDF 链接，对付费文章基本无效，所以和另外三个一起跳过。
- 8 秒取自交接时建议的 8–10 秒区间的下限。元数据响应是很小的 JSON，正常情况远低于这个值。

## 后果

两家都把一篇实际有开放版本的文献标成非 OA、且 Europe PMC 和 PMC 也没有收录时，这个版本会被漏掉，请求转由出版商等来源处理。

不保留跳过规则时，`git revert a6009c3` 即可恢复完整的 OA 回退；元数据超时是独立提交，不受影响。

## 验证要点

- 两家否定且零候选时跳过；单家否定、查询失败、有候选但下载失败时不跳过。
- 跳过后其余来源的相对顺序不变。
- 修改元数据超时不影响 PDF 下载的超时，也不改变缓存键。
