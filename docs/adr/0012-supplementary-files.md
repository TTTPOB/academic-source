# ADR 0012：补充材料先查 Europe PMC，再按出版商规则获取

- 状态：Accepted
- 实施情况：已实现。Nature、Elsevier、PLOS、bioRxiv/medRxiv、Science、Oxford 有专门规则，其余出版商使用通用的链接识别。

## 背景

原来的补充材料功能只有一套通用规则：读文章页，找看起来像补充文件的链接。它在多数出版商上拿不到文件：文章页被反爬拦截、文件清单在另一个页面、链接要登录状态才能下载。拿到的文件也没有说明，读者分不清哪个是哪个。

线上请求集中在少数出版商。按 DOI 前缀统计 223 篇：Nature 56、Elsevier 35、Science 18、bioRxiv 16、PLOS 14、Oxford 14。

## 决策

1. **先查 Europe PMC。** 文献被 Europe PMC 收录时，从它的全文 XML 读文件的标题和说明，从它的补充材料接口下载文件。这条路只用普通 HTTP，不受出版商反爬影响。拿到文件就不再访问出版商。
2. **Europe PMC 没有时走出版商规则。** 出版商策略提供两个钩子：要读哪些页面，以及页面上有哪些文件。没有专门规则的出版商使用通用识别。
3. **页面需要浏览器才能读到时，同源文件在同一个标签页里下载**，沿用页面的登录状态。跨域文件用携带浏览器 Cookie 的普通 HTTP 下载。
4. **产物带一段自由文本 `note`**，按原样记录标题、说明、原始文件名和来源页面。不把补充材料分成表格、图、数据集等结构化类别。
5. **只限制大小，不限制个数。** 单个文件 200 MB，一篇论文合计 600 MB。
6. **按文件类型校验内容。** 空文件、HTML 错误页、被截断的文件、扩展名与内容不符的文件不登记。补充材料可以是任何格式，不限于 PDF。
7. **提供只取补充材料的入口**：请求字段 `supplementary_only`，命令 `asource supp`。失败原因为 `supplementary_page_unavailable`、`supplementary_download_failed`、`supplementary_unavailable`。

## 理由与替代方案

- 结构化类别：各出版商的命名没有共同规律，强行归类会丢信息或归错。读者（多数是 agent）读原文说明就能判断。
- 限制每篇的文件个数：有的论文确实有几十个补充文件，按个数截断会丢掉有效内容。
- 为每个文件单独导航一个页面：更慢，也更容易触发验证。实测 Science 的补充文件可以在文章页的标签页里直接 `fetch` 到。

## 后果

- Europe PMC 的压缩包以它自己的文件名为准，与出版商页面上的文件名可能不同；`note` 里保留两者的对应关系。
- 没有专门规则的出版商仍然依赖通用识别，成功率没有保证。
- 文件经 CDP 以 base64 传输，大文件比直接下载慢。

## 验证要点

- 六家有专门规则的出版商各有一篇论文能取到补充文件，文件类型与页面所列一致。
- 被 Europe PMC 收录的论文不触发对出版商的请求。
- 没能保存的文件及原因出现在该篇结果的 `warnings` 里。
